# XMind 转标准测试用例

## 输入与输出

输入为 `.xmind` 文件或其完整主题树，以及调用方提供的被测应用名称。输出为 UTF-8 Markdown，每个 Scenario 对应一个用例；保留全部功能分支，不合并掉参数变体或边界场景。

在迁移工作流中，由 Test-Runner 指定本轮 sandbox 输出目录。macOS 路径示例：

- 输入：`/Users/<user>/MigrationWorkspace/.sdd-migration/inputs/cases.xmind`
- 输出：`/Users/<user>/MigrationWorkspace/.sdd-runs/<run_id>/runs/harmony/sandbox/<request>/converted.md`

调用方已提取主题树时，直接转换并仅返回 Markdown 正文，由调用方保存到上述受管目录。处理原始文件时使用现有 XMind 解析器；不在系统临时目录解压，不在输入文件旁生成输出。确需中间文件时使用本次 sandbox 请求下的 `runtime/temp/`，结束清理。

## 转换规则

1. Feature 表示功能分组，Scenario 表示用例，Given 表示前置条件，When 表示操作，Then 表示预期；保留标题、标签优先级及参数差异。
2. 标题包含辨别用例所需的功能上下文。步骤使用 `1、` 编号，按源顺序描述具体操作；前置条件在首个相关步骤括注。
3. 应用名称由调用方提供；提供时首步为“打开<应用>”，不从模块名猜应用名称，也不重复添加已有打开步骤。
4. 预期使用简练的可校验描述，多个断言以 `；` 分隔。中间 UI 反馈可跟随对应操作记录。
5. 不擅自删除用例、修正业务数值或补造缺失的验收条件；有歧义在对应预期中标记“待澄清：<具体缺项>”，保留原信息，交测试设计审核，不能冻结为通过标准。
6. 保留源知识、约束及必要上下文；不得因去重丢失用例依赖的信息。

## 输出格式

```markdown
## 用例描述：<功能上下文与标题>（<源优先级，如 P0>）

测试步骤：
1、打开<调用方提供的应用>
2、<动作及必要前置条件>
预期结果：<断言一>；<断言二>

---
```

源中没有优先级时不虚构。输出前核对 Scenario 数量、功能分支、参数、步骤及预期完整对应；转换结果是待审核测试设计，不代表测试已执行或通过。
